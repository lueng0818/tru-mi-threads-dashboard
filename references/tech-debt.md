## TD-01｜103 張卡片缺 `data-keywords`

**登記日**：2026-09-02
**狀態**：⏸ 待驗證，**不批次回填**
**阻擋於**：TD-02（schema 未定義）。TD-02 未結案前本項不得動工。
**現況**：217 張 post-card 中 114 張有 `data-keywords`，103 張沒有（覆蓋率 53%）。
缺值的卡片在 `filterKeyword` / `cardMatchesKw` 會退回全文比對。

### 為什麼不能當「純機械補值」處理

從卡片原文自動抽取關鍵字，至少牽涉三條**尚未定義**的規則：

1. **抽哪些詞** — 名詞？痛點詞？八類焦慮的分類語彙？沒有成文標準。
2. **正規化／同義詞** — 「硌手」「卡手」「刮手」算不算同一個 key？
   「戒圍」「尺寸」「size」呢？現有 114 張卡的處理方式沒有被記錄下來。
3. **舊卡是否適用現在的語彙** — 卡片橫跨 2024-03 至今，
   期間分類語彙已經變過。用現在的語彙回填舊卡，等於竄改歷史判讀。

### 動工前必須先完成的前置

- [ ] 逆向現有 114 張正常卡片，歸納出實際在用的生成規則與詞彙表
- [ ] 判定該規則能否 **100% deterministic** 重建（同一段原文永遠得到同一組 key）
- [ ] 能 → 寫腳本補值 → **逐張 diff 人工抽驗** → `dashboard_check.py` → 才寫回
- [ ] 不能 → 維持缺值，本項續留 technical debt，**不做近似回填**

### 明確不成立的動工理由

- ❌「讓 `dashboard_check.py` 的覆蓋率數字好看」
  → 健檢是用來擋錯的，不是用來通過的。同一條規則也適用於維運行為本身。
- ❌「反正只是加個 attribute，風險很低」
  → 風險不在寫入動作，在於用新推導覆蓋舊語意。

## TD-04｜卡片沒有「收錄日期」，無法機械汰舊

**登記日**：2026-09-02
**狀態**：🟡 已止血，歷史部分不補

`post-date` 是**原貼文**日期（最早到 2024-03），不是收錄日期，
所以現有 217 張卡無法用日期做汰舊或封存。

- 已做：SOP Step 5 要求新卡片帶 `data-collected="YYYY-MM-DD"`。
- **不做**：不用 DOM 順序反推歷史卡的收錄日。順序只是近似，
  寫進 attribute 之後就會被當成事實使用——這是 TD-01 的同一種錯。
- 待累積約三個月的 `data-collected` 之後，再評估是否需要封存機制。
